# Scenario corpus — v1 dataset card

**Contract**: `mfg-agentgraph-scenario-corpus-v1`
**Corpus ID**: `mimii-synthetic-context-v1`
**Version**: `v1`
**Release digest** (`sha256`): recorded in `corpus-v1.json` and printed by
`mfg-agentgraph-corpus verify`
**Development split digest**: recorded alongside it; this is the value a run manifest binds
**Description**: **MIMII-event-grounded synthetic-context** evaluation corpus

## What this release is

A versioned corpus for the anomaly-triage scenario across four machine classes (pump, fan,
valve, linear slide). It contains:

- **28 licensed source documents** reduced to 292 source-located procedural chunks;
- **8 authored assets** — two per machine class, one plant site;
- **64 authored sensors** over SSN/SOSA, eight measured properties per asset;
- **1,612 observations** — 4 MIMII-derived acoustic events and 1,608 authored-context records;
- **4 authored maintenance procedures** grounded in document chunks;
- **10 development-split queries** with expected evidence, expected action where justified,
  and a one-line rubric.

The serialised graph is **12,413 triples** in `urn:mfg-agentgraph:graph:corpus-context`.

## Lineage — what each element actually is

| Element | Lineage | Meaning |
|---|---|---|
| Documents + chunks | authored/curated | Licensed third-party text, excerpted by a declared rule |
| Assets, sites | authored/curated | MIMII supplies no asset hierarchy |
| Sensors | authored/curated | Synthetic SSN/SOSA grounding |
| 4 acoustic observations | **MIMII-derived** | One verified recording per machine class |
| 1,608 context observations | authored/curated | Generated by a declared rule; not measurements |
| Procedures | authored/curated | Written against the chunks they cite |
| Development queries | authored | Development split only |

A MIMII-derived observation must carry its recording identity and must declare
`label_source: mimii_dataset_label`. The corpus cannot express "a detector ran": no detector
was run, and the label is the dataset's.

### Verified MIMII inputs

Zenodo record **3384388**, version `public 1.0`, **CC BY-SA 4.0** (Hitachi Ltd.). Four archives
(`6_dB_pump/fan/valve/slider.zip`, 31.86 GB total) were **not** downloaded: each recording was
read from the remote ZIP by byte range, decompressed, and accepted only when its CRC32 and
declared size matched. All four verified at 10.0 s, 16 kHz, 8 channels, 16-bit.

The files are `WAVE_FORMAT_EXTENSIBLE` (tag 65534), which Python's `wave` module rejects;
the metadata above was read from the RIFF `fmt `/`data` chunks directly.

## Provenance and licences

Every document pins its primary URL, the SHA-256 of the downloaded artifact, the extraction
tool and version, and the reuse basis:

| Basis | Meaning |
|---|---|
| `public_domain_statutory` | 17 U.S.C. §105 — US federal work; third-party figures may still be embedded |
| `open_licence` | Explicit open licence (OGL v3.0, GFDL, CC BY-SA) |

**Share-alike obligations attach to three documents** and therefore to any derived text:
`doc:ose-universal-cnc-axis`, `doc:reprap-prusa-mendel`, `doc:v1e-lowrider`. The V1 Engineering
site states CC BY-SA while machine pages state CC BY-NC-SA 4.0; the conservative
non-commercial share-alike reading is recorded. Attribution for every document is in
`corpus-v1.json`.

`pdftotext` (poppler) is a **build prerequisite**, not a runtime dependency; its version is
recorded per document.

## Scale, and the honest shortfall

The frozen protocol's Track A asks for approximately 50 documents, four machine types,
multiple assets per type, and 10^4–10^5 triples. This release delivers 28 documents, all four
types, two assets per type, and 12,413 triples.

**The document count is short, and this card does not claim otherwise.** Verified reusable
documents exist beyond these 28, but four hosts refuse programmatic download from the authoring
environment even with browser headers:

| Host | Documents verified but not acquired |
|---|---|
| `www.nrc.gov` | 9 valve reports (NUREG/CR series) |
| `media.defense.gov` | several NAVEDTRA manuals |
| `www.cdc.gov` | NIOSH dust-control handbook |
| `publications.usace.army.mil` | USACE EM 1110-2-1150 family |

Archive.org and OSTI were checked for copies and hold none of the missing set. Acquiring them
requires a manual download; until then the protocol-scale claim is **unmet**, and any result
built on this release must say so.

Other limits:

- **Linear slides have no industrial seam.** No industrial linear-guide manufacturer grants
  reuse; the three slide documents are open-hardware documentation. Industrial slide-rail
  practice is not represented.
- Several pump sources are naval or community-handpump scale rather than industrial station
  scale; `relevance_tier` records whether the document is directly about the machine class
  (`T1`), names a unit (`T2`), or treats it as a component (`T3`).
- The chunk rule selects at most 12 procedural passages per document, so the chunks are a
  representative excerpt, not the full manual. The full artifact digest is pinned, so the
  excerpt is verifiable but the corpus is not a complete re-publication.
- 28 documents ≠ 28 independent maintenance philosophies; several are US Navy rate-training
  manuals with overlapping lineage.

## Leakage and split rules

- This split is **development only**; the contract rejects any other `split` value. Held-out
  questions are released by the blinded-packet issue and adjudicated references by the
  independent-annotation issue.
- The corpus, its context records and the development queries were authored **before** any
  strategy ran against them.
- Development queries may be used for prompt and index tuning; no held-out claim may cite
  this split.
- The context observations are generated by a declared rule
  (`_CONTEXT_OBSERVATIONS_PER_SENSOR = 25`, eight properties per asset). They are illustrative
  plant context, not measured data, and cannot support any claim about real asset behaviour.

## Reproduction

```bash
uv run python scripts/build_scenario_corpus.py            # download, extract, build
uv run python scripts/build_scenario_corpus.py --verify   # fail if a rebuild differs
uv run mfg-agentgraph-corpus verify evaluation/scenario-corpus-v1/corpus-v1.json
uv run mfg-agentgraph-corpus load   evaluation/scenario-corpus-v1/corpus-v1.json
```

`build` writes `corpus-v1.json` (canonical bytes) and `corpus-v1.trig`, and refuses to replace a
frozen release with different content. `load` publishes into the **corpus-context named
graph** using the same idempotent bootstrap as the deployment CLI, so it can never overwrite the
factory or provenance graphs; a divergent corpus graph is refused unless `--recreate` is passed.
Downloaded source artifacts are cached under `.cache/scenario-corpus/` and are never committed.

## Prohibited claims

- Any statement that this is MIMII maintenance decision support. MIMII supplies acoustic
  events only.
- Industrial decision quality, safety, operator trust, or field effectiveness.
- Topical breadth beyond the four classes and the documents listed.
- Protocol-scale (Track A) completeness, or any held-out score before the blinded and
  annotated releases exist.
- "Reproducible" in the packaged sense before the cold-start demonstration exists.
